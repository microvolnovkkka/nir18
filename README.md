# Аффект.МЭИ — научный блог НИР (nir18)

React + TypeScript + Vite, Go/net/http + pgx, PostgreSQL, Caddy и Docker Compose. Читатели могут искать и читать публикации. Участники команды входят по прямой ссылке и в своём рабочем разделе создают, редактируют и удаляют статьи. Таблицы, формулы KaTeX, код и изображения одинаково отображаются в предпросмотре и опубликованной статье. В «Моём разделе» доступен ИИ-бот для подготовки новых отчётов.

**Этап 2.3.5.** В рабочем разделе появился чат для новых отчётов. Из чата можно перенести ответ в общий Markdown-редактор, добавить изображения и подтвердить публикацию. Страница доступна участникам команды по адресу `/bot`.

## Быстрый локальный запуск

Понадобятся запущенный Docker с Compose и Git. Команды подходят для macOS, Linux и Git Bash.

### Если проект уже запускался

Из папки существующего клона выполните:

```sh
git switch codex/foundation
git pull --ff-only
```

Для генерации через DeepSeek проверьте две строки в существующем `.env` по [инструкции ниже](#настройка-бота). Если строки нет, добавьте её. Пароль действующей БД сохраните. Затем обновите контейнеры:

```sh
docker compose up -d --build
./scripts/check-local.sh
```

Откройте [рабочий раздел](http://localhost:8080/workspace) и обновите страницу. Используйте свой прежний пароль. Compose подключит существующие тома со статьями и изображениями при запуске из той же папки с тем же именем проекта.

### Первый запуск

Из папки, в которой хотите разместить проект:

```sh
git clone --branch codex/foundation https://github.com/microvolnovkkka/nir18.git
cd nir18
./scripts/init-env.sh
```

Скрипт создаст `.env` со случайным локальным паролем БД (требуется openssl). Если openssl отсутствует, скопируйте `.env.example` в `.env` и замените пароль случайной строкой **hex**; не публикуйте `.env`. По умолчанию бот работает в тестовом режиме. Для реальной генерации заполните `.env` по [инструкции ниже](#настройка-бота), затем запустите сайт. Миграции выполнятся автоматически.

```sh
docker compose up -d --build
```

Откройте [каталог](http://localhost:8080). Проверьте готовность сайта и базы данных:

```sh
./scripts/check-local.sh
docker compose ps -a
```

Ожидается `status: ready`, успешная SQL-проверка; `migrate` завершается с кодом 0 — это нормально. Каталог доступен сразу без входа. Для авторского аккаунта выполните шаги ниже. Полная проверка API на отдельной тестовой БД: `./scripts/test-api.sh` (нужен Go 1.26.1+). Инструкции Андрею — [серверный этап](docs/stages/03-api/README.md).

Остановить с сохранением данных:

```sh
docker compose down
```

Ключ `-v` удаляет тома со статьями, изображениями и аккаунтами. [Подробности запуска, миграций и диагностики](docs/stages/02-foundation/README.md)

## Настройка бота

Настройки лежат в **`.env` рядом с `compose.yaml`** на той машине, где запускается сайт. У локального стенда и сервера преподавателя свои файлы. Образец настроек хранится в [`.env.example`](.env.example). При обновлении Git сохраняет ваш `.env`, а `scripts/init-env.sh` пропускает существующий файл.

**Для тестирования интерфейса** достаточно `BOT_MODE=stub`. Ключ можно оставить пустым. Такой запуск даёт помеченный демонстрационный отчёт.

**Для генерации через DeepSeek** задайте в `.env` две строки. Впишите действующий ключ сразу после `DEEPSEEK_API_KEY=` во второй строке. Если строки уже есть, измените их на месте. Настоящий ключ храните только в личном или серверном `.env`.

```dotenv
BOT_MODE=model
DEEPSEEK_API_KEY=
```

Остальные параметры Compose подставляет сам. Задайте их в `.env`, если вашему стенду нужны другие значения.

| Переменная | По умолчанию в проекте | Назначение |
| --- | --- | --- |
| `DEEPSEEK_MODEL` | `deepseek-flash` | Модель для генерации отчётов |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | Базовый адрес API поставщика |
| `DEEPSEEK_THINKING` | `false` | Режим рассуждений модели (`true` для включения) |
| `DEEPSEEK_MAX_TOKENS` | `32768` | Верхняя граница длины ответа в токенах |
| `BOT_REQUESTS_PER_MINUTE` | `5` | Число попыток генерации в минуту на участника |

Если сайт уже работает и менялся только `.env`, примените настройки из корня проекта:

```sh
docker compose up -d api
```

Откройте `/bot` после входа и отправьте **новое** сообщение с темой и тезисами. Метка «Тестовая заглушка» у нового ответа означает, что обслуживающий запрос API работает в режиме `stub`. В режиме `model` ошибка доступности — повод проверить наличие ключа в `.env` этого стенда и доступ API к провайдеру.

## Как участникам войти на сайт

Публичной регистрации нет: пять аккаунтов создают миграции. Терминал нужен **только для первой установки или сброса пароля**, обычный вход выполняется в браузере. В публичной шапке и подвале ссылки на вход нет.

| Участник | Логин сайта |
| --- | --- |
| Фёдор Маврин | `fmavrin` |
| Александр Комаров | `akomarov` |
| Екатерина Кондратьева | `ekondrateva` |
| Андрей Воропаев | `avoropaev` |
| Егор Мушкетов | `emushketov` |

1. Запустите проект командами выше. На новой БД аккаунты ещё неактивны и без паролей.
2. В терминале **из корня репозитория** установите пароль своему аккаунту (замените логин):

   ```sh
   docker compose exec api /app/password -login fmavrin
   ```

   Дважды введите личный пароль: 12–128 символов, максимум 512 байт. Ввод не отображается — это нормально. Команда активирует существующий аккаунт; новых пользователей она не создаёт.
3. Откройте [http://localhost:8080/login](http://localhost:8080/login) напрямую и сохраните ссылку в закладки. Введите логин из таблицы и установленный пароль.
4. После входа откроется `/workspace`; в шапке появятся **«Мой раздел»** и **«Выйти»**. Нажмите **«Создать материал»**, заполните поля, добавьте изображение и откройте **«Предпросмотр»**. Команда **«Опубликовать»** запросит подтверждение. Чтобы изменить или удалить свою статью, откройте её из списка. До публикации текст хранится в открытой вкладке.
5. Для выхода нажмите **«Выйти»**: сессия отзывается, открывается публичная главная, личные кнопки исчезают. Сессия действует не более 7 суток; после истечения войдите снова через `/login`.

Забытый пароль устанавливается заново той же командой; это завершает все прежние сессии этого аккаунта. Без доступа к терминалу нужного сервера обратитесь к Фёдору. При обычном обновлении проекта и перезапуске с сохранённым томом устанавливать пароли повторно не нужно.

**У каждого локального запуска своя БД.** Пароль, установленный на компьютере Фёдора, не появится на компьютере Андрея после `git pull`. GitHub-аккаунт, пароль PostgreSQL из `.env` и аккаунт сайта — разные вещи. На общем сервере пароли устанавливает обслуживающий его разработчик; участники входят через `<адрес-сайта>/login`. Личные пароли не сохраняйте в Git/документации.

Отсутствие публичной ссылки — решение навигации. Сам адрес `/login` доступен любому; доступ к изменениям по-прежнему проверяют серверные сессии и авторство. Административной панели и выдачи ролей нет.

## Как подготовить отчёт с ботом

1. Войдите и откройте **Мой раздел → ИИ-бот** или перейдите на `/bot`. Укажите рабочий заголовок, направление и подтему. В чате вставьте исходные тезисы и фрагменты источников.
2. Нажмите **Отправить**. На уточняющий вопрос ответьте следующим сообщением. Под готовым отчётом нажмите **Сформировать черновик**. Перенос происходит в браузере без повторного вызова модели.
3. Во вкладке **Редактор Markdown** проверьте текст и добавьте изображения. Чтобы получить доработку, вернитесь в **Чат** с замечаниями. Если в редакторе уже есть текст, просмотрите предложенную замену и выберите **Применить** или **Оставить свой текст**.
4. Проверьте **Предпросмотр**, нажмите **Опубликовать** и подтвердите. После этого статья доступна в каталоге. До публикации чат и текст живут только в открытой вкладке браузера. Новый диалог можно начать с сохранением текста редактора.

**Рисунки в отчёте.** В чат передаётся только текст. Поставьте курсор в нужный абзац редактора, нажмите **Добавить изображение**, выберите файл и задайте описание. После вставки появится ссылка на загруженный рисунок. Если в тексте уже есть пометка для автора, выделите её перед загрузкой, чтобы заменить картинкой.

**Запланировано для бота.** Когда по материалам автора нужен рисунок, в самом ответе должна появляться текстовая подсказка в нужном месте, например «Здесь вставьте схему объединения признаков лица и рук». Автор заменит подсказку своим файлом в редакторе. Такую подсказку ещё предстоит добавить в инструкцию модели и проверить на отчёте.
