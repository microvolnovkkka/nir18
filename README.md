# Аффект.МЭИ — научный блог НИР (nir18)

React + TypeScript + Vite, Go/net/http + pgx, PostgreSQL, Caddy и Docker Compose. Реализован этап **2.3.2, часть 2**: вход, права автора, API публикаций и изображений. Добавлены публичный каталог, поиск/фильтры, чтение Markdown и экран входа. Редактор и чат ещё впереди; модуль DeepSeek существует отдельно, в основной сайт не подключён.

## Быстрый локальный запуск

Нужны Docker Engine/Desktop с Compose и Git. Команды из корня проекта в macOS/Linux/Git Bash:

```sh
git clone --branch codex/foundation https://github.com/microvolnovkkka/nir18.git
cd nir18
./scripts/init-env.sh
docker compose up -d --build
```

Скрипт создаст `.env` со случайным локальным паролем БД (требуется openssl). Если openssl отсутствует, скопируйте `.env.example` в `.env` и замените пароль случайной строкой **hex**; не публикуйте `.env`. Миграции выполняются автоматически перед API.

Открыть [localhost:8080](http://localhost:8080). Проверка:

```sh
./scripts/check-local.sh
docker compose ps -a
```

Ожидается `status: ready`, успешная SQL-проверка; `migrate` завершается с кодом 0 — это нормально. Каталог доступен сразу без входа. Для авторского аккаунта выполните шаги ниже. Полная проверка API на отдельной тестовой БД: `./scripts/test-api.sh` (нужен Go 1.26.1+). Инструкции Андрею — [серверный этап](docs/stages/03-api/README.md).

Остановить с сохранением данных:

```sh
docker compose down
```

**Не добавляйте `-v`**, если хотите сохранить данные томов. После изменений SQL/Go сначала пересоберите образ; подробный порядок миграций и диагностика — ниже.

## Как участникам войти на сайт

Публичной регистрации нет: пять аккаунтов создают миграции. Терминал нужен **только для первой установки или сброса пароля**, обычный вход выполняется в браузере. В публичной шапке и подвале ссылки на вход нет.

| Участник | Логин сайта |
| --- | --- |
| Фёдор Маврин | `fmavrin` |
| Александр Комаров | `akomarov` |
| Екатерина Кондратьева | `ekondrateva` |
| Андрей Воропаев | `avoropaev` |
| Егор Мушкетов | `emushketov` |

1. Запустите проект командами выше. На новой БД аккаунты ещё неактивны и без паролей.
2. В терминале **из корня репозитория** установите пароль своему аккаунту (замените логин):

   ```sh
   docker compose exec api /app/password -login fmavrin
   ```

   Дважды введите личный пароль: 12–128 символов, максимум 512 байт. Ввод не отображается — это нормально. Команда активирует существующий аккаунт; новых пользователей она не создаёт.
3. Откройте [http://localhost:8080/login](http://localhost:8080/login) напрямую и сохраните ссылку в закладки. Введите логин из таблицы и установленный пароль.
4. После входа откроется `/workspace`; в шапке появятся **«Мой раздел»** и **«Выйти»**. Пока в рабочем разделе есть ссылка на свои материалы; редактор и чат будут добавлены на следующих этапах.
5. Для выхода нажмите **«Выйти»**: сессия отзывается, открывается публичная главная, личные кнопки исчезают. Сессия действует не более 7 суток; после истечения войдите снова через `/login`.

Забытый пароль устанавливается заново той же командой; это завершает все прежние сессии этого аккаунта. Без доступа к терминалу нужного сервера обратитесь к Фёдору. При обычном обновлении проекта и перезапуске с сохранённым томом устанавливать пароли повторно не нужно.

**У каждого локального запуска своя БД.** Пароль, установленный на компьютере Фёдора, не появится на компьютере Андрея после `git pull`. GitHub-аккаунт, пароль PostgreSQL из `.env` и аккаунт сайта — разные вещи. На будущем общем сервере пароли устанавливает обслуживающий его разработчик; участники входят через `<адрес-сайта>/login`. Личные пароли не сохраняйте в Git/документации.

Отсутствие публичной ссылки — решение навигации. Сам адрес `/login` доступен любому; доступ к изменениям по-прежнему проверяют серверные сессии и авторство. Административной панели и выдачи ролей нет.
