# Начало работы над сайтом НИР

**Актуально: 28 октября 2026 года.** Это точка входа для следующего чата и участников команды. Проектирование и каркас 2.3.2, часть 1 подготовлены и проверены; предметные функции ещё не реализованы. Порядок чтения по ролям — [TEAM_GUIDE](docs/TEAM_GUIDE.md), запуск — [README](README.md).

## Что создаём

Научный блог по теме мультимодального распознавания эмоций и жестов. Пять участников публикуют результаты изучения; читатели открыто просматривают каталог, ищут и фильтруют статьи. ИИ-бот помогает оформить переданный текст в содержательный отчёт. Автор проверяет результат, добавляет изображения и подтверждает публикацию.

Технологии: **React + TypeScript + Vite → Go/net/http → PostgreSQL**, встроенный модуль бота с API DeepSeek, Markdown, Docker Compose + Caddy. Это сайт для НИР; реализация распознавания и ROS 2 в него не входит.

## Ключевые ограничения

- Публикации блога и отчёты НИР — одна сущность.
- Пять заранее созданных аккаунтов команды; публичное чтение без аккаунта. Каждый редактирует и после подтверждения удаляет только свои материалы. Направления/подтемы заполняются заранее; административные панели не нужны.
- Один общий Markdown-редактор и механизм предпросмотра для ручной работы и страницы бота.
- Бот готовит только новые статьи. «Сформировать черновик» переносит выбранный ответ без нового вызова модели; замена имеющихся правок — через «Применить». Опубликованные статьи редактируются вручную. Для публикации и сохранения правок требуется подтверждение автора.
- Нет сохранения черновиков и истории версий. До публикации содержимое — состояние браузера; серверные временные изображения допустимы.
- Бот получает текст, не открывает ссылки и не анализирует загружаемые изображения. PNG/JPEG/WebP вставляются отдельно через редактор.
- Обычный поиск и фильтры обязательны. Поиск через бота, редактор как в Word и разделённый экран — опции при наличии времени.
- «Обновлено», фильтр по датам и сортировка «сначала новые» используют дату последнего обновления.
- Сначала запускаем сайт локально с заглушкой бота. Модуль реального API делает второй разработчик; сервера, домена и купленного доступа пока нет.
- Уточнения текущего чата могут быть новее снимка ТЗ. Их статус указан в реестре решений; Google-документ автоматически не синхронизируется.

## Как работать по этапам

Результаты этапа 1 и части 1 этапа 2 находятся в [docs/stages](docs/stages/README.md). Следующая отдельная карточка — «Авторизация, проверка прав и базовое серверное API — 2.3.2, часть 2». Контракт бота подготовлен к согласованию, визуальные макеты ещё за content manager. Затем выполнять этапы 3–7 по готовности зависимостей. Не заменять эту последовательность созданием всего приложения одним неподтверждённым шагом.

Для каждого этапа фиксировать: сделано → как проверено → что остаётся → что нужно следующему этапу. Сроки в учебных неделях являются исходным планом; текущую неделю и реальную загрузку уточнять по фактическому ходу проекта. Репозиторий, домен и размещение не считать существующими только из-за упоминания в плане.
