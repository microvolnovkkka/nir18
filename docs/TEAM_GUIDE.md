# Единый путеводитель команды НИР

**Актуализация:** 9 ноября 2026 года. **Кому обязательно прочитать:** всей команде. **Какие разделы особенно важны:** 1–3 и своя строка в §4; промпт §5 перед передачей материалов нейросети.

## 1. Проект и статус

Создаём научный блог: опубликованные статьи одновременно служат материалами отчётности НИР. Сайт — Фёдор Маврин, модуль модели — Александр Комаров, интерфейс/контент — Екатерина Кондратьева, проверка — Андрей Воропаев, координация — Егор Мушкетов. Реализация распознавания/ROS 2 относится к будущей практике.

Работа локальная. Проектирование, каркас, серверная карточка 2.3.2 часть 2 и первые публичные страницы уже реализованы. Рабочее название — «Аффект.МЭИ», светлая морская/мятная палитра; текст «О проекте», правки PM, фильтры и анимированная композиция обновлены. Сверка с макетами и независимая приёмка ещё нужны. Факты и проверки — [статус](../DEVELOPMENT_STATUS.md), запуск — [README](../README.md), API и текущие границы — [03-api](stages/03-api/README.md).

Пять аккаунтов создаются заранее. Вход команды — напрямую через `/login`, без публичной ссылки; после входа — «Мой раздел» и «Выйти». Инструкция установки пароля и обычного входа — [README](../README.md#как-участникам-войти-на-сайт). Это авторский раздел, не админка. Каждая локальная БД независима.

Контракт бота 1.0 согласован Александром 01.11.2026, лимит 32768 принят Фёдором 07.11.2026. Модуль и отдельный тестовый стенд находятся в репозитории; живые измерения Александра — в `stages/02-foundation/DEEPSEEK_TEST_REPORT.md`. Общий редактор (2.3.4) и защищённая интеграция чата (2.3.5) ещё предстоят. Сервера/домена пока нет.

## 3. Статусы решений

- **Принято пользователем:** Q01–Q10 в реестре; пять аккаунтов и каталог заранее, вход только по прямой ссылке без публичной кнопки, автор меняет/удаляет только своё, одна дата обновления, общий Markdown-редактор, только новые отчёты с ботом, явное «Применить», без серверных черновиков/истории/автосохранения, ссылки не читаются, изображения отдельно.
- **Выбрано разработчиком технически:** cookie-сессии/Argon2id, UUID/ETag/квитанции, ILIKE+pg_trgm, 20 записей по умолчанию, lease изображений 24 часа и обновление каждые 10 минут. Основания в архитектуре/API/схеме. Это не отдельные продуктовые согласования пользователя.
- **Рекомендации:** окончательная визуальная подача и сверка страниц с предоставленными макетами; параметры хранения резервных копий перед размещением.
- **Ожидает человека:** совместная проверка бота с сайтом — Александр и Фёдор; вычитка/визуальная приёмка — Екатерина и Фёдор; независимая проверка — Андрей; сроки/часы — Егор; GitHub-аккаунты для приглашений на запись — участники. Публичное чтение репозитория аккаунтов не требует.
- **Ожидает внешнего ресурса:** будущие сервер/домен и место копий; для последующей генерации в основном сайте потребуется локально настроенный ключ DeepSeek. Не блокирует локальную часть.

Опциональны поиск через бота, Word-подобный редактор и разделённый экран. Не возвращать их как обязательные задачи. Сроки в учебных неделях — ориентир прежнего плана; календарные дедлайны этой работой не согласовывались.

## 5. Универсальный промпт для чатов с нейросетями

> Я участник команды НИР, моя роль — [роль], моя задача — [конкретная карточка]. Прочитай приложенные актуальные TEAM_GUIDE, требования, BOT_WORKFLOW, DECISIONS_AND_QUESTIONS, DEVELOPMENT_STATUS и документы моей роли. Сначала назови границы моей задачи и статус опорных документов. Используй единые требования и контракт сайта/бота; не изобретай несовместимые поля, маршруты и поведение. Не возвращай отменённые функции, серверные черновики, автосохранение, историю версий, файлы в чате, чтение ссылок и редактирование чужих статей. Проверяй указанный статус контракта: версия 1.0 подтверждена Александром; новые предложения не считай автоматически согласованными. Вход команды только по прямому `/login`, без публичной регистрации и ссылки входа. При противоречии укажи конкретные файлы и расходящиеся положения. Предлагаемые изменения отделяй от принятых решений; изменения общей границы согласуй с обоими разработчиками. Наличие плана или SQL-таблицы не означает готовности функции. Работай только в моей карточке и зафиксируй результат, проверки и оставшиеся вопросы.

После любого изменения требований/контракта автор изменения перечисляет затронутые файлы и дату, передаёт обновлённые версии всем зависимым ролям. Каждый участник повторно прикладывает их в свой чат и просит заменить старые версии. **Нейросеть не получает изменения из соседнего чата автоматически**, даже если оба участника работают над одним проектом. По возможности прикладывайте файлы одного Git-коммита; не смешивайте старый API и новый контракт.

## 6. Как передавать обновление

Фёдор передаёт ссылку на общий репозиторий либо актуальные Markdown и исходники без `.env`, node_modules, томов, архива и ключей. В сообщении: дата/коммит, что изменилось, кому перечитать, что требует согласования. Изменение общего контракта сначала обсуждают оба разработчика; затем обновляют документ, типы и тестовые примеры вместе. Готовые сообщения и точный список файлов — [TEAM_HANDOFF](TEAM_HANDOFF.md). Сообщения подготовлены для Фёдора, автоматически никому не отправляются.
