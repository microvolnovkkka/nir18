Несовместимое изменение требует новой версии контракта, а не молчаливой правки одной стороны.

## 1. Назначение и запреты

Модуль получает текст для **нового** отчёта, возвращает Markdown или просьбу уточнить данные. Он не принимает файл, не открывает URL, не получает байты изображений, не обращается к БД сайта, не назначает автора/дату, не публикует и не обновляет статьи. Общие объяснения допустимы; вымышленные источники, эксперименты и результаты команды запрещены. Нехватка исходных данных обозначается явно. Проверка автором обязательна и не заменяется промптом.

Нет поля publication_id и сценария редактирования опубликованной статьи. После публикации фронтенд завершает сценарий нового отчёта. Сервер не способен по произвольному вставленному тексту установить, был ли он когда-то опубликован: он запрещает привязку генерации к операции обновления, а не обещает семантически распознать любой скопированный текст.

## 2. Внешний HTTP: браузер → Go-сервер сайта

`POST /api/bot/respond`, сессия участника + Origin + X-CSRF-Token. JSON, никаких query/path-параметров и multipart. Один запрос — один полный ответ, без потоковой выдачи.

| Поле запроса | Тип | Правило |
| --- | --- | --- |
| contract_version | string | строго `1.0`; неподдерживаемая версия — 422 contract_version_unsupported |
| request_id | string UUID | создаёт браузер для одной попытки; сервер использует в ответе/X-Request-ID после проверки |
| topic | object | обязательные `subtopic_id` (целое, существующая подтема), `title` (тема нового отчёта, 1–200 символов) |
| message | string | новое сообщение пользователя, 1–20 000 символов |
| history | array | предыдущие сообщения, 0–20 элементов; текущее message не повторяется |
| history[].role | string | только user / assistant; system/tool запрещены |
| history[].content | string | 1–20 000 символов; суммарно history ≤ 80 000 символов |
| current_markdown | string | текущее содержимое редактора; пустая строка до переноса; ≤ 200 000 символов/800 000 байт |

Общий JSON ≤ 2 МиБ. Значения проверяются до вызова модуля; неизвестные поля, в том числе author/date/publication_id/image_bytes, отклоняются. Тема — текст, каталог подтемы проверяет сайт. `history` содержит только текст текущего чата, не скрытые рассуждения модели. При превышении лимита интерфейс предлагает начать новый диалог, сохранив редактор; молча обрезать историю нельзя.

Пример первого запроса:

```json
{"contract_version":"1.0","request_id":"40000000-0000-4000-8000-000000000001","topic":{"subtopic_id":101,"title":"Категориальные модели эмоций"},"message":"Оформи обзор по моим заметкам: категории эмоций описывают дискретные состояния. Экспериментов мы не проводили. Источники пока не подобраны.","history":[],"current_markdown":""}
```

200:

```json
{"contract_version":"1.0","request_id":"40000000-0000-4000-8000-000000000001","mode":"stub","kind":"report","markdown":"## Тестовый ответ\nЭто демонстрационная заглушка, а не результат модели.\n\n## Материал автора\nКатегории эмоций описывают дискретные состояния.\n\n## Ограничения\nИсточники нужно добавить и проверить. Эксперименты не проводились.","warnings":["Тестовый режим: реальная генерация не подключена."]}
```

Поля ответа: contract_version/request_id — эхо проверенного запроса; mode — `stub` или `model` (определяет конфигурация сервера, не браузер); kind — `report` или `clarification`; markdown — непустая строка ≤ лимита редактора; warnings — массив до 10 строк по ≤ 500 символов (может быть пуст). Только report допускает перенос в редактор. `clarification` показывает вопрос в чате, кнопки переноса нет. Любой Markdown выводится безопасным рендерером.

Пример запроса доработки:

```json
{"contract_version":"1.0","request_id":"40000000-0000-4000-8000-000000000002","topic":{"subtopic_id":101,"title":"Категориальные модели эмоций"},"message":"Добавь короткий вывод, сохрани рисунок и мои правки.","history":[{"role":"user","content":"Подготовь обзор по моим заметкам."},{"role":"assistant","content":"## Обзор\nКатегории описывают дискретные состояния."}],"current_markdown":"## Обзор\nУточнённый автором текст.\n\n![Схема категорий](/media/30000000-0000-4000-8000-000000000001)"}
```

Совместимый ответ может вернуть тот же текст с выводом, но обязан сохранить точную вставку картинки. Здесь не приводится второй самостоятельный формат ответа: используется структура 200 выше.

### Ошибки

```json
{"error":{"code":"bot_timeout","message":"Не удалось дождаться ответа. Можно повторить запрос.","fields":{}},"request_id":"40000000-0000-4000-8000-000000000002"}
```

Общие 400/401/403/413/415/422 из REST API; неверная версия — 422 `contract_version_unsupported`. Дополнительные:

| HTTP / code | Причина | Действие интерфейса |
| --- | --- | --- |
| 409 bot_busy | для пользователя уже выполняется запрос | дождаться/отменить; Retry-After: 2 |
| 422 media_context_invalid | входной Markdown содержит чужую/недоступную/неподдерживаемую картинку | исправить вставки/повторить загрузку |
| 429 rate_limited | лимит сайта или провайдера | Retry-After, затем ручной повтор |
| 502 bot_invalid_response | неправильная структура/лимит ответа | сохранить ввод, разрешить явный повтор |
| 502 bot_media_mismatch | ErrMediaMismatch: потеря, изменение или добавление изображения/лишнего повтора в результате | не разрешать применение; сохранить ввод, показать причину и предложить явный повтор |
| 503 bot_unavailable | поставщик недоступен/не настроен | сохранить ввод, сообщить; не подменять незаметно реальную модель заглушкой |
| 504 bot_timeout | превышен дедлайн | отменить внутренний вызов, предложить повтор |

Валидный request_id сохраняется и в ошибке; при сломанном JSON/ID сервер назначает свой. Секреты, endpoint с токенами, сырой ответ поставщика и внутренние рассуждения не возвращаются пользователю.

## 3. Внутренний интерфейс: Go-сервер → встроенный Go-модуль

Не HTTP и не микросервис. Пакет интерфейса — `backend/internal/bot`, реализация подключается при сборке сервера. Никакой зависимости React от поставщика.

```go
type Responder interface {
    Respond(ctx context.Context, input Input) (Output, error)
}
type Topic struct {
    SubtopicID int16
    DirectionID int16
    SubtopicName string
    DirectionName string
    Title string
}
type Message struct { Role string; Content string }
type Input struct {
    RequestID string
    Topic Topic
    Message string
    History []Message
    CurrentMarkdown string
    ProtectedImages []string
}
type Output struct {
    Kind string
    Markdown string
    Warnings []string
}
type Failure struct { Code string; RetryAfterSeconds int }
```

`Failure` реализует error; Code: unavailable, rate_limited, invalid_response; тайм-аут/отмена — context.DeadlineExceeded/context.Canceled. Сайт переводит ошибки в HTTP, определяет mode и добавляет contract_version/request_id. Внутренний Output не содержит автора, даты и публикации. Поля Topic.Direction*/SubtopicName сервер получает из справочника, не доверяет клиентским именам. `ProtectedImages` — точные Markdown-вставки изображений из current_markdown, в порядке появления, включая повторные. Это только текст, не данные картинки. Контекст пользователя/сессии остаётся у сайта и не отправляется поставщику.

Отдельная типизированная ошибка модуля `ErrMediaMismatch` переводится сервером в **HTTP 502, code `bot_media_mismatch`**. При такой ошибке результат модели не передаётся для применения. Проверка существования изображения и прав владельца остаётся на стороне сайта; это не обязанность модуля.

По подтверждению Александра, модуль получает от модели JSON с `kind`, `markdown`, `warnings`, проверяет его и возвращает существующий `Output`. Поля `contract_version`, `request_id`, `mode` добавляет сайт. Диагностика времени, токенов и рассуждений относится к отдельному тестовому стенду и не добавляет поля в основной payload; текст `reasoning_content` в браузер сайта не передаётся.

Реальный модуль должен быть безопасен для конкурентных вызовов, не хранить диалог между запросами, учитывать ctx для HTTP-вызова поставщика, ограничивать размер ответа, разбирать только ожидаемую структуру, возвращать типизированные ошибки. Системная инструкция собирается модулем; пользовательские строки и history не становятся системными инструкциями. Данные запросов не логируются в обычном журнале.

## 4. Сохранение картинок и действия только во фронтенде

1. Сайт разбирает current_markdown в AST, проверяет каждое изображение `/media/<uuid>` и владельца/доступность. В первой версии внешние/data/SVG-картинки не поддерживаются. Reference-style Markdown разрешён редактором только после нормализации в inline `![alt](/media/id)` перед запросом. Экранирование alt сохраняется.
2. Сайт передаёт точные inline-вставки в ProtectedImages; модуль получает указание оставить их без изменения. Удаление картинки автором **до запроса** законно: её уже нет в current_markdown и ProtectedImages.
3. До выдачи report сервер сравнивает мультимножество точных вставок в результате с входным: ни потери, ни изменения alt/URL, ни новых/лишних повторов. Не извлекать картинки из блоков кода как реальные вставки. Несовпадение — bot_media_mismatch; ничего не дописывается молча. Для clarification запретить новые изображения, перенос не предлагается.
4. Фронтенд хранит снимок current_markdown на момент отправки только в памяти. Ответ привязан к этому снимку. «Сформировать черновик» переносит выбранный report без HTTP-запроса. Если редактор заполнен, перенос доступен только через «Применить» после просмотра предлагаемой замены.
5. Если редактор изменился после запроса, интерфейс предупреждает, что ответ не учитывает последние текстовые правки. Выбор старого report по-прежнему не вызывает сеть. Фронтенд строит новое предложение локально: если набор изображений отличается от текущего редактора, удаляет реальные image-узлы из копии ответа и добавляет в конец блок «Изображения автора» с **текущими** точными вставками в исходном порядке/количестве. Это сохраняет новые картинки и не возвращает намеренно удалённые. Перемещение явно показано до применения, автор может отказаться или расставить изображения вручную после применения. Изображения из блоков кода не трогать. При одинаковом наборе сохраняются позиции из ответа. Новый вызов модели возможен только отдельной отправкой сообщения, не как условие кнопки переноса.
6. Предложение привязывается к текущему снимку редактора при его показе. При нажатии «Применить» фронтенд повторно проверяет этот снимок и набор ссылок. Если редактор снова изменён, локально пересобирает предложение по пункту 5 и просит сначала просмотреть обновлённый результат, не применяет старый. Поля заголовка/подтемы не заменяются ответом автоматически. Текстовые ручные правки могут быть заменены только этим явным действием. Файлы/связи БД при применении не меняются.

При первой генерации current_markdown пуст, поэтому ответ не должен придумывать внутренние media URL. Сервер снова проверяет изображения при публикации независимо от проверки бота. Точные позиции картинок относительно переработанного текста автор оценивает в предпросмотре; автоматического распознавания содержимого изображений нет.

## 5. Ожидание, отмена и повтор

Рабочие настройки: общий дедлайн сервера 90 секунд, запрос поставщику не дольше оставшегося ctx; тайм-аут браузера 100 секунд; прокси не обрывает раньше 110 секунд. Один активный вызов на пользователя и не более 5 попыток/минуту (конфигурируется). Ограничение конкурентности хранится в памяти единственного Go-процесса; горизонтального масштабирования пока нет.

**Стартовая настройка генерации: `max_tokens=8192`** (`DEEPSEEK_MAX_TOKENS=8192`). По сообщению Александра, модуль допускает настройку до 32 768 токенов. Лимит Markdown в 200 000 символов/800 000 байт — предел проверки, а не обещанный размер сгенерированной статьи: фактический объём ограничен токенами и временем. Точный токеновый бюджет входа пока не подсчитывается; предельные сочетания истории, сообщения и редактора нужно проверить реальными запросами.

Александр подтвердил прерывание вызова по дедлайну 90 секунд и учёт более короткого ctx сайта. **Успешная генерация за 90 секунд пока не подтверждена.** Скорость, качество, оба режима модели и окончательные лимиты уточняются после реальных испытаний; превышение дедлайна означает 504 `bot_timeout`.

Кнопка «Отменить» вызывает AbortController. Разрыв запроса отменяет Go request context, модуль отменяет свой HTTP-вызов. Ответ, пришедший после отмены/смены request_id, фронтенд игнорирует. Если соединение уже закрыто, сервер не обещает доставить JSON об отмене. Отмена не гарантирует, что поставщик не начислил оплату за уже начатую обработку.

Нет автоматических повторов ни во фронтенде, ни в модуле. «Повторить» создаёт новый request_id и повторяет сохранённый снимок запроса, если редактор не изменён; иначе запрашивает с актуальным контекстом. request_id — корреляция, не ключ дедупликации и не хранилище ответа. Потерянный результат может потребовать новой оплачиваемой генерации; это не создаст публикацию. Квитанции публикаций к боту не применяются. Ни история, ни ответы не пишутся в БД/файлы сайта.

## 6. Заглушка и совместимость

Заглушка реализует тот же Responder, работает без сети/ключа, возвращает kind=report, заметный тестовый текст и предупреждение. При непустом current_markdown возвращает его с тестовым примечанием, сохраняя вставки. Управление задержкой/ошибкой задаётся конструктором заглушки в тестах/конфигурации сервера, не скрытыми командами пользователя. Проверяем обычный ответ, задержку, unavailable, rate_limited, deadline/cancel. На этапе каркаса интерфейс/заглушка проверяются напрямую; HTTP endpoint ещё не подключён, чтобы не обходить будущую авторизацию.

Общая приёмка на заглушке, затем повтор с настоящим модулем:

- Запросы из §2 проходят типизацию, неизвестные поля отклоняются; обе стороны понимают версию и kind.
- Report переносится без нового сетевого вызова; clarification остаётся чатом.
- Доработка учитывает именно CurrentMarkdown, а не только History.
- Два одинаковых изображения, экранированный alt, ссылка в коде, удалённая автором вставка и чужой ID проверяются раздельно; потерянная/лишняя картинка блокирует результат.
- Поздний ответ после отмены не меняет редактор; выбранный старый ответ строит локальное предложение с текущими изображениями без нового вызова модели.
- При ошибках сохраняются ввод и текущая работа; «Применить» и «Опубликовать» — разные действия.
- Текст «добавь автора/дату/опубликуй/прочти ссылку» не получает новых системных полномочий.
- После подключения поставщика отдельно проверяются настоящий ответ, тайм-аут, недоступность, лимиты, отсутствие вымышленных источников на подготовленных примерах. Успех заглушки не доказывает качество модели.

Параметры подключения из ответа Александра: официальный API DeepSeek, `https://api.deepseek.com`, `POST /chat/completions`, модель `deepseek-flash`, обычный режим и режим с рассуждением, без стриминга. Это стартовая конфигурация для испытаний, а не результат реального вызова в рамках этой работы.

Шаблон `.env.example` содержит `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`, `DEEPSEEK_THINKING`, `DEEPSEEK_MAX_TOKENS`. Ключ заполняется только на сервере локально. Точное строковое значение `DEEPSEEK_THINKING` в ответе не указано: перед подключением его нужно сверить с конфигурационным парсером переданного модуля. До этого поле в шаблоне оставлено пустым. Добавление переменных в шаблон само по себе не подключает модуль и не передаёт их контейнеру; это задача интеграции.
