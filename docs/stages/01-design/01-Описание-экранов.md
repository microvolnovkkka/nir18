# 01. Задание на схемы экранов

**Дата:** 28.10.2026. **Статус:** спроектировано; схемы и визуальные макеты готовит content manager. Это не готовый интерфейс.

**Кому обязательно прочитать:** Екатерине (content manager), Фёдору (сайт), Андрею (тестирование).
**Какие разделы особенно важны:** Екатерине — 1–8; Андрею — состояния и подтверждения; Александру — раздел 6 вместе с [контрактом](04-Контракт-бота.md).

Источник обязательного поведения — [требования](../../../TZ_2_1_BLOG_REQUIREMENTS.md) и [сценарий бота](../../../BOT_WORKFLOW.md). Ниже результат проектирования. Слова «рекомендуется» описывают компоновку, которую Екатерина может улучшить, сохранив функции и доступность. Светлая тема принята; цвета, логотип и декоративные эффекты не назначены.

## 1. Карта страниц

| URL | Назначение | Доступ / основные переходы |
| --- | --- | --- |
| `/` | Каталог: направления → подтемы → статьи, поиск и фильтры | Всем; состояние фильтров в query string |
| `/publications/:id` | Чтение одной публикации | Всем; автору «Редактировать», «Удалить» |
| `/about` | Тема, цель, команда и пять направлений | Всем; назад в каталог |
| `/login` | Вход участника | Всем; уже вошедшему — переход в рабочий раздел |
| `/workspace` | Собственные опубликованные статьи | Только участнику; «Создать вручную», «Новый отчёт с ботом» |
| `/workspace/new` | Новый материал вручную | Только участнику; редактор → предпросмотр → подтверждение |
| `/workspace/publications/:id/edit` | Ручное обновление статьи | Только её автору; чужой материал открывается для чтения, редактирование запрещено сервером |
| `/bot` | Новый материал с ботом | Только участнику; три вкладки и общий редактор |
| прочие | Страница «Не найдено» | Всем; ссылка в каталог |

Направление и подтема — состояние каталога, а не обязательные дополнительные страницы. Отдельных страниц регистрации, администрирования и серверных черновиков нет. Гость на закрытом экране получает переход ко входу с безопасным относительным `returnTo`; после входа возвращается туда. После публикации сценарий `/bot` завершается, последующая правка — по ручному маршруту.

## 2. Общая рамка и состояния

На ПК рекомендуется шапка: название проекта, «Каталог», «О проекте», справа «Войти» либо имя, «Рабочий раздел», «ИИ-бот», «Выйти». Основная область ограничена по ширине для чтения. На телефоне — название, кнопка меню, вертикальное содержимое; текущее место видно по заголовку и хлебным крошкам. Навигация доступна с клавиатуры, фокус видим, у кнопок есть текстовые названия.

Общие состояния: загрузка обозначена текстом/индикатором; ошибка содержит понятное объяснение и «Повторить»; успех сообщается только после ответа сервера. Ошибка не закрывает редактор и не стирает поля. При истечении сессии предложить вход в отдельной вкладке и повтор действия, сохранив открытую работу в памяти. Выход и уход со страницы с изменениями требуют предупреждения о потере несохранённого текста; перезагрузка/закрытие не обещают восстановления. Вкладки внутри редактора не считаются уходом.

Ожидающее действие временно блокирует свою кнопку. Ошибки валидации показываются рядом с полями и общей сводкой; фокус переносится к первой ошибке. Подтверждения — доступные диалоги с заголовком, «Отмена» и точным названием действия; закрытие возвращает фокус к исходной кнопке. Сообщения об успехе/ошибке доступны скринридеру.

## 3. Каталог и статья

### Каталог

Блоки: заголовок, пять направлений, список подтем выбранного направления, строка поиска, фильтры автора и диапазона дат «Обновлено», результаты, число результатов, пагинация. Рекомендуется на ПК располагать каталог слева, поиск и выдачу справа; на телефоне — поиск сверху, сворачиваемые фильтры, затем карточки. Состояние выбранных фильтров видно даже при свёрнутой панели.

Карточка: заголовок-ссылка, автор, направление/подтема, «Обновлено». Текстовый анонс можно добавить позднее, обязательным полем он не является. «Найти»/Enter применяет фильтры, «Сбросить» очищает их; переключение направления сбрасывает неподходящую подтему. Выбор подтемы без направления автоматически подставляет её направление. Любое изменение фильтра возвращает на страницу 1. Страницы «Назад»/«Далее» и номер; размер по умолчанию 20, подробная семантика — [API](03-REST-API.md).

Состояния: первоначальная загрузка; ошибка с повтором; каталог без публикаций («Публикаций пока нет»); поиск без совпадений («Измените или сбросьте фильтры»); успешная выдача. Предыдущую выдачу при обновлении можно оставить с пометкой загрузки, но не выдавать за результат нового запроса. Поиск обычный, без вызова бота.

### Статья

Хлебные крошки, заголовок, автор, направление/подтема, одна дата «Обновлено» (Europe/Moscow), тело Markdown, раздел источников внутри текста. На ПК — центральная колонка; на телефоне — вся доступная ширина с полями, горизонтальная прокрутка только таблиц/кода. Изображения вписываются в ширину, сохраняют пропорции, имеют alt-текст. Формулы отображаются тем же рендерером, что предпросмотр.

Кнопки автора размещаются рядом с метаданными или под ними; читателю и другим авторам не показываются. «Редактировать» ведёт в ручной редактор. «Удалить» открывает подтверждение с названием статьи и предупреждением, что восстановления через сайт нет. Успех возвращает в рабочий список, ошибка оставляет статью. При 404 — «Материал не найден или удалён». Это не обещание различить два случая.

## 4. Вход, рабочий список, «О проекте»

Вход: логин, пароль с переключением видимости, «Войти»; без регистрации и восстановления по email. Неверный вход — единое сообщение без раскрытия существования аккаунта; ограничение попыток — время повторной попытки. Успех ведёт в `returnTo` либо `/workspace`. На телефоне форма одной колонкой, рекомендуемая ширина на ПК — компактная центральная карточка.

Рабочий список: имя автора, две кнопки создания, список его статей с заголовком, подтемой, «Обновлено» и действиями «Открыть», «Редактировать», «Удалить». Использует тот же API списка с `author_id` текущего пользователя и пагинацией. При пустом списке — приглашение создать первый материал. На телефоне действия переносятся под заголовок. Удаление требует того же диалога, что на статье.

«О проекте»: тема и цель из PROJECT_CONTEXT, граница между теоретической НИР и будущей практикой, команда и исследовательские направления. Рекомендуется текстовая страница; таблица команды на телефоне превращается в последовательные карточки. Сведения предоставляет Екатерина; учебные роли не означают административных прав.

## 5. Общий Markdown-редактор и предпросмотр

Один компонент для ручного создания, ручного обновления и страницы бота. Сверху заголовок, направление, зависимая подтема, имя автора. Для нового материала дата: «Будет назначена при публикации», для существующего — текущее «Обновлено» с пояснением, что оно изменится после сохранения.

Вкладки ручного экрана: «Редактор Markdown» / «Предпросмотр». Поля статьи и текст сохраняются в памяти родительского компонента. В редакторе: панель вставки заголовка, списка, таблицы, ссылки, кода, формулы и изображения; большое текстовое поле. На ПК панель над полем; на телефоне кнопки переносятся строками, вкладки доступны без горизонтального прокручивания всей страницы. Разделённый экран не требуется.

«Добавить изображение»: выбор PNG/JPEG/WebP, поле описания, ход загрузки, ошибка/повтор. После успеха вставляется `![описание](/media/<id>)` в сохранённую позицию курсора. Замена — загрузка нового файла и изменение ссылки, старый файл до успешного сохранения остаётся доступен прежней статье. Удаление вставки — изменение Markdown; отдельной кнопки немедленного уничтожения файла нет. Лимиты 5 МиБ и 20 Мп отображаются рядом с выбором файла. Потерявшие срок временные изображения помечаются: требуется повторная загрузка, публикация с несуществующей ссылкой запрещена.

Предпросмотр показывает заголовок, автора, выбранный каталог, текст и изображения. Один безопасный рендерер с поддержкой таблиц, ссылок, блоков кода и формул. Сырой HTML не исполняется; источники оформляются Markdown-разделом, автоматической библиографии нет. Внешние изображения в первой версии не подключаем: загрузить файл через редактор; внешние обычные ссылки допустимы.

«Опубликовать» открывает диалог: название, направление/подтема, автор, «Опубликовать»/«Отмена». «Сохранить изменения» для существующей статьи открывает аналогичный диалог «Обновить публикацию». До ответа сервера читатели видят прежний материал. При успехе — ссылка на статью и завершение текущего сценария. При конфликте правок из другой вкладки — объяснение, сохранение введённого текста на экране, возможность скопировать его, открыть свежую статью и вручную перенести правки; автоматического слияния/истории нет.

## 6. Страница бота — обязательно для разработчика бота

Верх: «Новый отчёт», заметная метка **«Тестовая заглушка — реальная модель не подключена»** в тестовом режиме, тема/подтема и три вкладки «Чат / Редактор Markdown / Предпросмотр». На ПК и телефоне вкладки переключаются, а не обязаны показываться одновременно.

Чат: текущая история, поле темы и сообщения, «Отправить», во время ожидания «Отменить», при ошибке «Повторить». Файлового поля и кнопки чтения URL нет. Рядом пояснение: вставьте текст; ссылки служат только указанием источников. Готовый ответ имеет «Сформировать черновик»; ответ с просьбой уточнить данные не выдаётся за готовый отчёт. Сетевой запрос происходит только при отправке/явном повторе. Перенос выбранного ответа выполняется локально.

Если редактор пуст, выбранный готовый ответ переносится сразу. Если заполнен, показать предложенный результат отдельно и кнопку «Применить» с предупреждением о замене текстовых правок. Пока она не нажата, текущий текст остаётся. Если модуль потерял изображения запроса, результат отклоняется. Если редактор изменён позже либо выбран старый ответ, интерфейс предупреждает о замене поздних правок и локально готовит предложение с текущими изображениями по контракту: при различии набора они явно показываются в конце блока «Изображения автора». Дополнительной генерации по кнопке переноса нет. Точное правило сохранения вставок и состояний — только в [контракте v1](04-Контракт-бота.md).

Пустой чат содержит короткую инструкцию и необязательный пример текстового ввода. Ошибка/отмена сохраняет и чат, и редактор; возвращает возможность отправки. Повтор не происходит автоматически, поскольку может стоить денег после подключения модели. Генерация никогда не публикует материал; предпросмотр и подтверждение используют общий сценарий раздела 5.

## 7. Что передаёт content manager

Схемы ПК и телефона для каталога, статьи, входа, рабочего списка, общего редактора/предпросмотра, трёх вкладок бота; варианты пустых состояний, ошибок и трёх подтверждений. Можно использовать любой удобный инструмент. Подготовить пример статьи с таблицей, формулой, кодом и картинкой, подписи кнопок и вычитанный текст «О проекте».

Каталог для старта берётся из PROJECT_CONTEXT §5: пять направлений, по три первоначальные подтемы; точные идентификаторы и названия — в стартовой миграции. Екатерина проверяет соответствие, не создаёт отдельную несовместимую копию. Новые подтемы/названия согласуются как изменение справочника.

## 8. Проверка схем до реализации

Для каждого маршрута показать путь гостя и участника, ПК и телефон; проверить фокус, длинные названия, отсутствие статей, неверный вход, истечение сессии, потерю сети, медленную генерацию, превышение лимита картинки, отмену диалогов и повторную отправку. На схемах не должно быть серверного «Сохранить черновик», редактирования чужого отчёта и кнопки бота для опубликованной статьи.
