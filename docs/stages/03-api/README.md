## Запуск и пароли

Из корня проекта:

```sh
git switch codex/foundation
git pull --ff-only
# Только при первом запуске:
./scripts/init-env.sh
docker compose up -d --build
./scripts/check-local.sh
```

Сайт: http://localhost:8080. Используйте именно `localhost`, если он указан в APP_ORIGIN: адрес `127.0.0.1` имеет другой Origin и запросы записи будут отклонены. На HTTPS обязательна COOKIE_SECURE=true. Никаких ключей модели для этого этапа не нужно.

Пять аккаунтов: `fmavrin`, `akomarov`, `ekondrateva`, `avoropaev`, `emushketov`. Изначально они неактивны. Пароли в рабочей БД автоматически не назначались. Для нужного участника выполните:

```sh
docker compose exec api /app/password -login fmavrin
```

Введите пароль дважды без отображения: 12–128 символов, максимум 512 байт. CLI активирует **существующий** аккаунт и отзывает все его старые сессии в одной транзакции. Та же команда сбрасывает пароль. Пароля в аргументах, логах, миграциях и Git нет. Для автоматизации есть `-stdin`: одна строка из защищённого источника, без `echo` с реальным паролем в истории терминала. Не выполняйте сброс чужого пароля в общей рабочей БД ради тестирования.

Проверить `/login`, затем `/workspace`; выйти через кнопку в шапке. Пока рабочий раздел показывает личный вход и ссылку на собственные материалы. Создание и правки доступны через API; редактор ещё впереди.

## Как устроена запись

Cookie хранит случайный токен; PostgreSQL — только его SHA-256. Сессия живёт 7 дней. Origin проверяется на каждой записи, X-CSRF-Token берётся из login/me. Сервер сам назначает автора. Для пяти участников изменения одного владельца последовательно блокируют его строку users; внутри транзакции сессия проверяется ещё раз. Сброс пароля не оставляет ранее начатому запросу возможность записать данные после отзыва.

Публикации требуют Idempotency-Key; обновление и удаление — также If-Match. Квитанция и изменение сохраняются атомарно. Повтор не создаёт статью и не меняет её дату. Проверки авторства, версии и файлов выполняются в транзакции. COUNT и выдача каталога читаются в одном снимке REPEATABLE READ. Даты фильтров — Москва, поля updated_at — время сервера.

Загрузка сохраняет staging → файл на диск → ready. Установка финального имени сделана атомарным hard link в пределах одного тома, без перезаписи существующего файла, затем удаляется временное имя. Это техническое уточнение механизма вместо обычного rename, который способен перезаписать файл; формат API не меняется. После fsync файла/каталогов фиксируется ready. Неудачная загрузка остаётся staging для уборки и не выдаётся читателям.

PNG/JPEG/WebP проверяются по содержимому, размерам и полному декодированию; максимум 5 МиБ/20 Мп, два декодирования одновременно. Изображения принадлежат автору; чужое публичное изображение нельзя привязать к своей статье. Приватная выдача и уборка используют блокировку строки media. Снятие последней связи даёт минимум 24 часа. Фоновая уборка раз в час удаляет истёкшие ready и staging старше часа, повторяет deleting; связанные файлы не трогает. Неизвестные файлы без записей автоматически не сканируются: обслуживание сирот и полный backup/restore остаются эксплуатационным этапом 2.3.6.

Лимиты входа за 15 минут: LOGIN_PAIR_LIMIT=5, LOGIN_IP_LIMIT=30; незавершённые попытки временно занимают лимит, успешные освобождают его. Лимитер в памяти одного процесса; перезапуск сбрасывает счётчики. Временные загрузки: TEMP_MEDIA_COUNT=100, TEMP_MEDIA_BYTES=524288000 на автора. Настройки меняются в `.env` и требуют пересоздания API. IP берётся из RemoteAddr; только в закрытой сети Compose включён TRUST_PROXY, Caddy **перезаписывает** X-Nir-Client-IP. Не публикуйте порт API в обход Caddy с TRUST_PROXY=true.

## Проверки для Андрея

Требования: Docker и Go 1.26.1+. Запуск из корня:

```sh
./scripts/test-api.sh
```

Скрипт создаёт отдельную временную PostgreSQL с тестовым паролем и случайным локальным портом, запускает `go test -race -count=1 ./...`, удаляет только созданный тестовый контейнер. Рабочие тома и пароли не меняются. Каждый интеграционный прогон использует собственную схему. Без TEST_DATABASE_URL обычный `go test ./...` **пропускает** интеграционный тест — это не полная приёмка.

Проверяются: неизвестный/неверный вход, cookie/CSRF, выход/отзыв, лимит попыток, два разных автора, запрет чужих правок/удаления/изображений, ETag-конфликт, одинаковые параллельные повторы и конфликт ключа, справочники/совместные фильтры/буквальный поиск, приватные и публичные картинки, HEAD, аренда, отсутствующий физический файл, отложенная очистка. Вредоносные/повторные/неизвестные JSON-поля отклоняются.

Фронтенд (Node >=22.12, pnpm 11.25.0):

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

Тест рендерера проверяет таблицы, формулы, внутренние изображения и запрет исполняемого HTML/опасных URL/внешних картинок. Ручная приёмка: ПК и телефон, выбор направления/подтемы, поиск, даты и сброс, пустая выдача, вход/ошибка/выход, чтение статьи с таблицей/формулой/изображением. Результат автоматических тестов не заменяет независимую приёмку Андрея.
