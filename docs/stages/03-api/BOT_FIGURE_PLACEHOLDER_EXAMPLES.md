# Проверка подсказок для рисунков

28 ноября 2026 года выполнены два реальных запроса к официальному API DeepSeek через страницу /bot отдельного локального Docker Compose стенда. Модель в конфигурации — deepseek-flash, режим размышления выключен, предел выхода — 32768 токенов. Версия системного промпта — nir18-2026-11-28.1.

Промпт находится в backend/internal/bot/prompt.txt и встраивается в Go-модуль при сборке API. Оба запроса вернули HTTP 200 и kind=report.

| Сценарий | Время HTTP запроса | Результат |
| --- | --- | --- |
| Первый черновик с недостающим Рисунком 1 | 4,041 с | Подсказка после описания метода и напоминание в warnings |
| Доработка с готовым Рисунком 1 и недостающим Рисунком 2 | 6,465 с | Первая вставка сохранена, новая подсказка добавлена к обработке пропусков |

## Запрос 1

Подготовь короткий теоретический черновик до 250 слов. Исходные заметки: видео разбивается на кадры с временными метками; MediaPipe Hands даёт 21 точку кисти; координаты нормализуем относительно запястья; в окне кадров вычисляем смещения и маску пропусков, затем передаём признаки классификатору. Для пояснения этой последовательности предусмотрен Рисунок 1 — схема обработки видеокадров и формирования признаков. Файл схемы ещё не загружен. В заметках нет результатов обучения, метрик и библиографических источников.

Фрагмент полученного Markdown

```markdown
В окне кадров $[i-W+1, i]$ вычисляются смещения $\Delta \tilde{p}_{i,k} = \tilde{p}_{i,k} - \tilde{p}_{i-1,k}$ и маска пропусков, отмечающая кадры или точки, для которых детекция не получена. Полученный вектор признаков передаётся классификатору.

Здесь вставьте Рисунок 1 — схему обработки видеокадров и формирования признаков.
```

Массив warnings из ответа

```json
[
  "Вставьте Рисунок 1 через вкладку «Редактор Markdown» — схема обработки видеокадров и формирования признаков.",
  "Результаты обучения, метрики и библиографические источники в материалах отсутствуют — раздел ограничений это отражает."
]
```

## Запрос 2

Рисунок 1 уже вставлен в текущий Markdown. Доработай статью, сохрани краткий объём и опиши обработку пропусков: отсутствующие точки отмечаем маской; скорости для пропущенного перехода не вычисляем; длинный разрыв разделяет наблюдение на отдельные сегменты. Для этого пояснения предусмотрен Рисунок 2 — схема ветвления при пропуске ключевых точек. Его файл пока не загружен. Метрик качества и источников по-прежнему нет.

Фрагмент полученного Markdown

```markdown
Отсутствующие точки отмечаются в маске. Если для перехода между соседними кадрами точка не детектирована хотя бы в одном из них, скорость (смещение) для этого перехода не вычисляется — вместо значения используется отметка пропуска в маске. При достаточно длинном разрыве непрерывное наблюдение разделяется на отдельные сегменты, и признаки последующих окон не смешивают кадры по разные стороны разрыва.

Здесь вставьте Рисунок 2 — схему ветвления при пропуске ключевых точек.
```

Массив warnings из ответа

```json
[
  "Вставьте Рисунок 2 через вкладку «Редактор Markdown» — схема ветвления при пропуске ключевых точек.",
  "В текущем черновике отсутствуют данные о пороговом значении «длинного разрыва» и правиле выбора размера окна W — эти параметры следует уточнить перед публикацией.",
  "Метрики качества и библиографические источники не предоставлены; раздел «Источники» требует дополнения и проверки."
]
```
