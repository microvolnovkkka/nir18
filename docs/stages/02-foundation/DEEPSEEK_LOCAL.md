# Реальный модуль DeepSeek и отдельный локальный стенд

Модуль использует промпт `nir18-2026-11-06.1` из `backend/internal/bot/prompt.txt`. В его основе утверждённый `SYSTEM_PROMPT_NIR.md` с уточнениями по формату JSON и работе с защищёнными вставками. Модуль совместим с `bot.Responder` и [контрактом `1.0`](../01-design/04-Контракт-бота.md).

## Назначение

Модуль `internal/bot.DeepSeek` реализует `Respond(context.Context, Input) (Output,error)`. Системная инструкция встроена через `go:embed`; принимает тему, историю, новый текст, актуальный Markdown и точные ProtectedImages. Конфигурация читается через `DeepSeekConfigFromEnv`, конструктор — `NewDeepSeek(config, httpClient)`.

Основной `cmd/api`, React, Compose, авторизация и публичные маршруты не изменены. До готовности защищённого `/api/bot/respond` реальную модель можно проверить через отдельный `cmd/bot-playground` на loopback:8090 либо через `cmd/deepseek-check`. Локальный стенд не должен публиковаться в интернете или подключаться к основному сайту как обход авторизации.

## Конфигурация

| Переменная | Значение |
| --- | --- |
| DEEPSEEK_API_KEY | Обязательна для настоящей генерации; только окружение сервера |
| DEEPSEEK_BASE_URL | По умолчанию https://api.deepseek.com; путь /chat/completions добавляется клиентом |
| DEEPSEEK_MODEL | По умолчанию deepseek-flash |
| DEEPSEEK_THINKING | true/false; режим CLI, если не переопределён флагом; в стенде выбирается отдельно для каждого запроса |
| DEEPSEEK_MAX_TOKENS | 32768 по умолчанию. Допустимые значения от 256 до 32768 |

Go не загружает `.env` автоматически. Ключ используется только в Authorization: Bearer. Удалённый endpoint должен использовать HTTPS; HTTP разрешён только для loopback-тестов. Переходы по HTTP redirect запрещены. История, материалы, ответы и рассуждения не пишутся в журналы и файлы модулем/стендом. Явная команда CLI печатает только финальный проверенный ответ и безопасную диагностику.

## Форматы и границы

Поставщику отправляется Chat Completions с `stream:false`, явным `thinking.type`, `response_format:{"type":"json_object"}` и отдельной системной инструкцией. Ожидается одна завершённая choice с role=assistant и finish_reason=stop.

Строка content должна содержать ровно объект:

```json
{"kind":"report","markdown":"# Тема\n\nМатериал.","warnings":[]}
```

Допускается kind=clarification. Неизвестные/повторные/пропущенные поля, null, лишний JSON, неправильные типы, пробельный content, finish_reason=length и превышение лимитов отклоняются. Reasoning_content разбирается отдельно и используется только для подсчёта длины. Общий дедлайн не более 90 секунд, чтение ответа поставщика ограничено 8 МиБ. История user/assistant, лимиты текста и предупреждений соответствуют черновику контракта. Повторов и скрытого fallback на заглушку нет.

Метод `RespondMeasured` дополнительно возвращает Diagnostics. Это инструмент испытаний, а не расширение `bot.Output` или JSON основного сайта. В результате нет рассуждений, сырых ошибок, ключей и текста промпта.

Стенд использует отдельный адрес `POST /local/generate`, собственную тестовую оболочку request/response+diagnostics и не меняет `/api/bot/respond`. Вложенное поле response демонстрирует внешний ответ сайта: contract_version, request_id, mode, kind, markdown, warnings. При интеграции эти поля должен добавлять сервер сайта, а не сама модель.

## Изображения

`ProtectedImages(markdown)` разбирает CommonMark AST с Goldmark 1.8.7 и получает исходные вставки по позициям image-узлов. Изображения в fenced/indented code и code span игнорируются. Сохраняются точные исходные строки, экранированный alt и повторения. Поддерживается нормализованный inline-формат `![alt](/media/UUID)` без title; reference-style и внешние/data-картинки отклоняются. Сырой HTML также отклоняется.

Input.ProtectedImages сверяется с текущим текстом. В report результат должен содержать такое же мультимножество точных вставок; в clarification реальных изображений быть не должно. Ошибка помечается `ErrMediaMismatch` и оборачивает `Failure{Code:"invalid_response"}`. Сервер сайта может проверить errors.Is(err, bot.ErrMediaMismatch) раньше общего Failure и вернуть `502 bot_media_mismatch`.

Проверка существования/владения файлами остаётся у основного сайта. Стенд без БД проверяет только синтаксис: примеры с искусственными UUID не доказывают права или наличие изображений. Модуль не открывает ссылки и не анализирует байты картинок.

## Локальная защита

Команда разрешает bind только на явный loopback IP. Проверяются RemoteAddr и Host против DNS rebinding; POST требует тот же Origin и случайный X-Local-Token, получаемый страницей через same-origin GET. CORS не разрешается. CSP исключает внешние ресурсы; вывод через textContent. Один активный запрос на процесс, не более 5 вызовов в минуту. AbortController отменяет fetch и HTTP request context, который передаётся DeepSeek. Снятие оплаты поставщиком после начала обработки не гарантируется отменой.

Эти меры предназначены для одного разработчика на localhost. Они не заменяют cookie-сессию, права, CSRF, проверку каталога и media основного сайта. Не регистрируйте этот обработчик в публичном Router и не добавляйте его в Compose web/API.

## Передача Фёдору

1. Сохранить существующий Responder и три поля Output.
2. Подтвердить предлагаемый JSON внутри content и критерии clarification.
3. Создать реальный Responder из серверной конфигурации и внедрить в защищённый обработчик после авторизации.
4. Заполнять Topic из каталога, проверять роли/лимиты/картинки, передавать текущий Markdown.
5. Переводить context timeout/cancel и Failure в ошибки §2 контракта; отдельно media mismatch.
6. Применять снимки редактора и сохранение текущих изображений на фронтенде по §4 контракта; «Сформировать черновик» не вызывает модель повторно.
7. Провести реальные испытания ключом и зафиксировать время, модель, режим, версию промпта, usage и нарушения. Успех httptest не является измерением DeepSeek.

6 ноября 2026 года выполнены 14 живых запросов и пять контролируемых проверок ошибок. В [отчёте](DEEPSEEK_TEST_REPORT.md) приведены время, токены и замечания к содержанию. Для интеграции предстоит подключить модуль в защищённом обработчике основного сайта.
