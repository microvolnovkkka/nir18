# Проверка резервного копирования и восстановления

22 ноября 2026 года выполнен полный цикл на трёх отдельных Docker Compose проектах `nir18-backup-qa-cf3093a`, `nir18-backup-qa-cf3093b` и `nir18-backup-qa-cf3093c`. Все 13 проверок прошли. После окончания тестовые контейнеры и тома удалены.

Среда проверки — Windows, Git Bash и Linux-контейнеры Docker Desktop. Базовая версия сайта — `e123761`, PostgreSQL 18, схема БД версии 2. Скрипты дополнительно прошли синтаксическую проверку в Git Bash и Linux `sh`. Отдельно проверены точность инвентаризации файлов и завершение с ошибкой при сбое вычисления SHA-256.

## Результаты

| Проверка | Фактический результат |
| --- | --- |
| Подготовка данных | Через настоящий HTTP API загружен PNG и опубликована статья со ссылкой на него |
| Согласованная копия | Архив создан, ранее работавший API снова готов принимать запросы |
| Повторная операция обслуживания | Вторая операция отклонена по блокировке, API продолжает работать |
| Повреждённый архив | Отказ до создания контейнера БД |
| Путь с `../` внутри архива изображений | Отказ до создания контейнера БД |
| Работающий API целевого проекта | Восстановление отклонено, сайт остаётся доступным |
| Непустая целевая БД | Восстановление отклонено, существующая статья сохранена |
| Отсутствующий файл готового изображения | Создание копии завершается ошибкой, итоговый архив отсутствует, API снова запущен |
| Другая major-версия PostgreSQL в метаданных | Отказ, целевая БД остаётся пустой |
| Непустой целевой том изображений | Отказ, целевая БД остаётся пустой |
| Полное восстановление после удаления обоих томов | Текст и PNG совпадают с исходными, старые сессии завершены, чужое редактирование получает HTTP 403 |
| Копия без изображений при остановленном API | Архив создан, API остаётся остановленным |
| Восстановление копии без изображений | Восстановлены пять участников, статьи и изображения отсутствуют |

## Контроль полного цикла

Статья `125631ba-ab0e-443a-a631-6ad571d2523c` создана с изображением `edc30824-2ae4-4d75-8501-635583083f87`. Через API получены HTTP 201 для загрузки и публикации. В БД перед копированием были одна статья, одно изображение, одна сессия и одна техническая квитанция операции.

После создания архива выполнено удаление контейнеров и обоих томов этого тестового проекта. Отдельно подтверждено отсутствие томов `postgres_data` и `media_data` перед запуском `restore.sh`.

Сразу после восстановления в БД снова находились одна статья и одно изображение, а число сессий и квитанций стало равно нулю. До явного запуска API в проекте работал только PostgreSQL.

После запуска через Caddy статья и изображение вернули HTTP 200. Текст статьи совпал с исходным посимвольно, PNG совпал побайтово. SHA-256 изображения до и после восстановления совпал.

```text
04c1ad415a95ea3d190a5193a4e83f1f155619b03b381860fd2d4228c1e5f079
```

Запрос со старой сессией вернул HTTP 401. Участники вошли с сохранёнными паролями. При попытке другого участника обновить восстановленную статью сервер вернул HTTP 403.

Архив тестовых данных имел размер 7904 байта. Создание копии с возобновлением API заняло 17,109 с. Восстановление с запуском PostgreSQL и проверками заняло 22,578 с. Указанное время восстановления заканчивается до запуска API. Эти значения относятся к маленькому тестовому набору.

Машинные результаты сохранены в [BACKUP_RESTORE_TEST.json](BACKUP_RESTORE_TEST.json). Порядок запуска приведён в [инструкции](BACKUP_RESTORE.md). Приёмка на сервере проекта выполняется после локальной проверки.
